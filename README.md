O padrão de projeto Injeção de Dependências é uma forma de fazer com que uma classe receba os objetos de que precisa (suas dependências) de fora, em vez de criá-los dentro dela. Isso deixa o código mais flexível, fácil de manter e de testar, porque uma classe não precisa saber como suas dependências são criadas, apenas como usá-las. No Spring Boot, esse padrão é aplicado automaticamente por meio do container de Inversão de Controle (IoC), que é responsável por criar e gerenciar os objetos da aplicação, chamados de beans. Assim, quando uma classe precisa de outra, o Spring fornece automaticamente a instância correta. Por exemplo, imagine uma classe PedidoService que precisa enviar e-mails ao confirmar um pedido. Em vez de ela mesma criar um novo EmailService com new EmailService(), o Spring injeta essa dependência automaticamente: basta declarar private final EmailService emailService e deixar o Spring cuidar da criação e ligação entre elas. Com isso, se amanhã for necessário trocar o serviço de e-mail por outro, não é preciso modificar o PedidoService, apenas fornecer uma nova implementação. Esse mecanismo de injeção é uma das principais razões pelas quais o Spring Boot facilita o desenvolvimento de aplicações bem organizadas e com baixo acoplamento entre as partes.
